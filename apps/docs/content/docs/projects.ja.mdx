プロジェクトは、複数の[タスク](/issues)で完了する作業を整理するための単位です。プロダクトのリリース、移行、段階的に進める機能などが該当します。

1 件のタスクで説明できる作業にプロジェクトは不要です。プロジェクトが適しているのは、共通の目標を持ち、進捗をまとめて追跡したい、あるいは同じリポジトリで進める一連の作業です。

## プロジェクトの構成

| 内容 | 役割 |
|---|---|
| **名前、アイコン、説明** | 目標、範囲、長期にわたって有効な要件。説明はプロジェクト内で作業するエージェントの実行コンテキストに入ります。 |
| **組織** | プロジェクトが属する組織、または **組織なし**。 |
| **優先度** | `urgent`、`high`、`medium`、`low`、`none`。 |
| **リード（lead）** | メンバーまたはエージェント。プロジェクトの調整役を示します。 |
| **タスクと進捗** | プロジェクト内の作業と、その完了割合。 |
| **リポジトリ** | プロジェクトが作業する GitHub リポジトリ。リポジトリごとにチェックアウトとワークレーンを持ちます。 |

![プロジェクト詳細: ステータス別のタスク、進捗、プロジェクトの説明](/images/docs/project-detail.webp)

## 組織

組織はプロジェクトをまとめるものです。たとえば、プロジェクトが対象とする会社や顧客ごとにまとめます。1 つのプロジェクトは最大 1 つの組織に属します。**新規プロジェクト**では組織の選択が必須で、プロジェクトのプロパティの **組織** 行で変更できます。

- **プロジェクト** ページはプロジェクトを組織ごとに名前順でまとめ、組織のないプロジェクトは最後の **組織なし** に表示します。グループの行をクリックすると折りたたまれます。
- サイドバーでプロジェクトの次にある **組織** ページは、すべての組織とそれぞれのプロジェクト数を一覧にします。行をクリックすると組織のページが開き、その組織のプロジェクトが表示されます。そこで **新規プロジェクト** を押すと、その組織に属するプロジェクトを作成できます。
- **新しい組織** では名前とキー（key）を入力します。組織名は大文字と小文字を区別せずに重複できません。
- **キー** は組織のフォルダ名です。英小文字、数字、ダッシュのみを使い、英字か数字で始まり、ワークスペース内で一意である必要があります。組織のページで変更できます。

組織の名前の変更や削除はできません。

## プロジェクトとタスクの関係

1 つのプロジェクトは任意の数のタスクを含むことができ、1 つのタスクは最大 1 つのプロジェクトに属します。タスクはプロジェクト内で直接作成することも、タスクのプロパティでプロジェクトを選択・変更することもできます。

プロジェクトの進捗は、紐づくタスクから自動的に計算されます。

```text
進捗 = ステータスが done または cancelled のタスク数 ÷ プロジェクト内の全タスク数
```

`cancelled` はその作業がプロジェクトの範囲から終了したことを意味するため、進捗に数えられます。

## プロジェクトの説明と実行コンテキスト

エージェントがプロジェクト内のタスクを実行するとき、プロジェクトの名前と説明がその実行のコンテキストに追加されます。説明には、関連するすべての実行に必要な情報 — 目標、技術的な境界、成果物の取り決め — を書きます。1 件のタスクにだけ関係する要件は、そのタスクに書いてください。

## リポジトリ

プロジェクトは作業する GitHub リポジトリを持ちます。プロジェクトのページでは、ヘッダーにリポジトリ数が表示され、`owner/name` 順にリポジトリごとのカードが並びます。カードにはデフォルトブランチとワークレーンが表示され、最初はリポジトリのチェックアウトにある `main` です。カードのヘッダーをクリックすると折りたためます。**プロジェクト**と組織のページでは、プロジェクトの行を開くとリポジトリごとに 1 行が表示されます。

- **リポジトリ**で**リポジトリを追加**が開きます。ワークスペースの [GitHub App](/github-integration) が参照できるすべてのリポジトリが、非公開か公開か、デフォルトブランチとともに一覧表示されます。リポジトリが属するプロジェクトは最大 1 つです。すでに別のプロジェクトにあるリポジトリにはそのプロジェクト名が表示され、選択できません。**見つかりませんか？GitHub で Multica にアクセスを許可**を押すと App のインストールページが開きます。
- **チェックアウト**では、マシンとリポジトリの通常のチェックアウトのフォルダを選びます。初期値は `~/Repos/{name}` です。Multica はそのマシンでフォルダを確認します。フォルダはそのリポジトリの git チェックアウトで、デフォルトブランチ上にある必要があります。フォルダがなければ、**ここにクローン**でクローンします。
- **リリース**では、リポジトリのバージョンの取得元を選びます。チェックアウトで見つかったバージョンファイル（`pubspec.yaml`、`Cargo.toml`、`pyproject.toml`、`package.json`）、**タグのみ**、または**このリポジトリはリリースしない**のいずれかです。
- **インストール**では、新しい worklane の依存関係をインストールするコマンドを選びます。Multica はデフォルトブランチで `pnpm-lock.yaml`（`pnpm install`）、`package-lock.json`（`npm ci`）、`yarn.lock`（`yarn install`）、`pubspec.yaml`（`flutter pub get`）、`uv.lock`（`uv sync`）を探し、見つかったコマンドをすべて表示して最初のものを選択します。**なし**や、自分で入力したコマンドも選べます。**リポジトリを編集**では保存済みのコマンドが表示され、まだない場合は探します。
- カードのメニューには**リポジトリを編集**と**リポジトリを削除**があります。編集ではチェックアウトとリリースを変更できますが、リポジトリ自体は変えられません。削除ではリポジトリとワークレーン `main` が Multica から削除され、チェックアウトのフォルダはマシン上にそのまま残ります。`main` 以外のワークレーンがあるリポジトリは、それらを先に削除するまで削除できません。

## worklane

worklane はリポジトリ内の作業レーンで、1 台のマシン上に専用の git worktree を持ちます。どのリポジトリにも、リポジトリのチェックアウトで作業する `main` があります。

- リポジトリのカードの **worklane を追加**、または Projects と組織のページのリポジトリ行にある **+ Worklane** で、**新しい worklane · {owner/name}** が開きます。**名前**はリポジトリ内で一意です。**フォルダー**は名前から小文字とハイフンで入力され、リポジトリの worklane の中で一意です。**ランタイム**には、リポジトリのチェックアウトがあり worktree を作成できるオンラインのマシンが表示されます。**Worktree** には worktree の場所 `~/Worktrees/{organisation key}/{repository}/{folder}`、開始ブランチ、インストールコマンドが表示されます。
- **worklane を作成**は、マシン上で手順を順に実行します。デフォルトブランチの取得、worktree の追加、依存関係のインストールです。失敗した手順はエラーとともに**再試行**を表示し、すべての手順が通るまで worklane は保存されません。完了すると worklane のページが開きます。
- worklane のページには、リポジトリ、作業中または空き、タイムライン、アクティビティが表示されます。アクティビティには、誰がどのマシンで作成したか、各名前変更、リポジトリのリリースの変更が並びます。
- worklane のメニューには**名前を変更**と**削除**があります。名前を変更してもフォルダーと worktree はそのままです。削除はマシン上の worktree を削除し、Multica から worklane を削除します。マシンがオフラインのとき、または worktree にコミットされていない変更やデフォルトブランチにないコミットがあるときは、理由を示して削除を拒否します。`main` は名前変更も削除もできません。
- リポジトリのカード、プロジェクトのヘッダー、Projects と組織のページの行には、`main` を含む worklane の数が表示されます。

## プロジェクトリード

リードはメンバーまたはエージェントで、プロジェクトの調整役を示します。権限設定ではないため、プロジェクト内のタスクが自動的に割り当てられることはなく、エージェントをリードにしても自動的に実行されることはありません。実行を開始するには、これまでどおりタスクの割り当て、@メンション、またはオートパイロットのトリガーが必要です。

## worklane で作業する

worklane のページは、タスクを 3 つのビューで表示します。ページ上部でビューを選びます。ページは **タイムライン** で開きます。

- **タイムライン** は、リポジトリのラインのリリースを順に表示し、それぞれに含まれるこの worklane のタスクを表示します。
- **ボード** は、worklane のタスクをステータスごとの列で表示します。**キャンセル済み** の列は非表示です。カードを別の列にドラッグするとステータスが変わります。Multica は「REBL-76 をIn Reviewに移動しました」と知らせ、変更に失敗したときはカードを元に戻します。列の **+** は、その列のステータス、この worklane、リポジトリの次のリリースを入れた **新規タスク** を開きます。
- **リスト** は、ラインの順にリリースごとのセクションを表示します。バージョンと状態、タイトル、手動で設定したバージョンには **手動で設定**、この worklane のタスクの進み具合（例：「3 件中 1 件完了」）または **この worklane のタスクはありません**、リリースのメニューと説明、そしてタスクが続きます。その後に、リリースのないこの worklane のタスクを集めた **リリースなし** が、該当するタスクがあるときだけ続きます。

どのビューでもタスクをクリックすると、ビューの横にプレビューが開きます。プレビューの上部には種類、ID、タイトル、ステータス、worklane、リリース、担当者が並び、その下に説明が続きます。**タスクを開く** でタスク自身のページを開きます。

上部の **種類** フィルターで 8 種類の中から 1 つ以上を選ぶか、種類のないタスクには **種類なし** を選びます。すると、どのビューも選んだ種類だけを表示し、ビューを切り替えても選択は保たれます。

### 作業中と空き

worklane のタスクのうち In Progress か In Review のものが worktree のブランチを使っている間、worklane は **作業中** で、それ以外は **空き** です。上部には何に取り組んでいるかが表示されます。

- 作業中のときは、ブランチを使っているタスクを **作業中：{ID} {タイトル}** で表示します。
- 空きのときは、完了でもキャンセル済みでもない最初のタスクを **次：{ID} {タイトル}** で表示します。リリースをラインの順に見てからリリースなしを見て、それぞれの中では最初に作成されたタスクを選びます。
- worklane のすべてのタスクが完了またはキャンセル済みのときは、どちらも表示しません。

### worklane の worktree で作業するエージェント

worklane のタスクに対するエージェントのタスク実行は、その worklane の worktree で、タスクのブランチ上で行われます。`main` はリポジトリのチェックアウトで実行されます。worklane は一度に 1 つのタスクだけを実行します。エージェントのランタイムが worklane と別のマシンにある場合、タスクは拒否され、その理由が表示されます。

ブランチを使っているタスクのプルリクエストがデフォルトブランチにマージされると、worktree は取得したデフォルトブランチから作った次のタスクのブランチに切り替わります。残っているタスクがなければ detached の状態になります。切り替えるのは何も失われないときだけです。コミットしていない変更やプッシュしていないコミットがあると、worktree は今のブランチにとどまり、worklane のアクティビティにその理由が残ります。

## リリース

リポジトリのリリースは、リリースする順に並んだ 1 本のラインになります。リポジトリのどの worklane も、**タイムライン** に同じラインを表示します。最初の未リリースのリリースが **次のリリース**、その後のものが **計画中** です。worklane の上部には **最終リリース v{バージョン}**、**まだリリースなし** または **リリースしない** と表示されます。プロジェクトと組織のページでは、worklane の各行に、リポジトリの前回と次回のリリースが **前回 · 次回 · 計画中のリリース** の下に表示されます。リリースをクリックすると、その worklane のタイムラインで開きます。

- タイムラインの最後にある **リリースを計画** は、最後のリリースの後にリリースを追加します。**パッチ**、**マイナー**、**メジャー** を選ぶと、前のリリース（最初のリリースでは最新のタグ）のバージョンを上げます。**カスタム** を選ぶとバージョンを手動で設定します。どのバージョンも前のものより高くなければなりません。そうでない間は、ダイアログが理由を示し、**リリースを計画** は無効のままです。
- 手動で設定したバージョンには **手動で設定** と表示され、ラインが変わっても番号は変わりません。上げたバージョンは前のリリースに合わせて変わります。
- 未リリースのリリースのメニューには **リリースを編集**、**前へ移動**、**後ろへ移動**、**リリースを削除** があります。**リリースを編集** はバージョン、タイトル、説明を変更します。リリースを移動または削除すると、その後の上げたバージョンが振り直されます。前のものより高くないバージョンが生じる移動は、理由とともに無効になります。
- 変更はそれぞれ、リポジトリのすべての worklane のアクティビティに残り、変わったバージョンごとに「Notifications v1.2.0 -> v1.1.0」のような行が付きます。

リリースには、リリースするまで日付も目標もありません。

### リリースしないリポジトリ

**リポジトリを編集** で **リリース** を **このリポジトリはリリースしない** にすると、その worklane には「リリースを計画」の代わりに「{owner/name} はリリースしないため、その worklane はリリースを計画しません。」と表示されます。ラインに未リリースのリリースが残っている間は、リポジトリはリリースをやめられません。リポジトリを編集がそれらを挙げ、先に削除するよう求めます。**タグのみ** かバージョンファイルを選び直すと、リリースを計画は最新のタグから始まります。

## worklanes とリリース

**worklanes** と **リリース** はサイドバーの「作業」の下、組織の次にあります。どちらのページもワークスペースの作業を組織、プロジェクト、リポジトリごとに、プロジェクトページと同じ順序で一覧表示し、表示する内容のないグループは表示しません。すべてのグループは展開された状態で開きます。矢印かグループの行をクリックすると折りたたまれます。組織名やプロジェクト名をクリックするとそのページが開きます。

- **worklanes** はすべての worklane を一覧表示し、各リポジトリの下では `main` が先頭です。各リポジトリにはデフォルトブランチと **+ Worklane** が表示され、クリックするとそのリポジトリの新しい worklane が開きます。worklane の行には、作業中の内容とリリースが表示されます：最後に出荷したリリース、この worklane のタスクについての「{done}/{total}」付きの次のリリース、その後の計画中のリリース最大 2 件。行をクリックすると worklane のタイムラインが開きます。
- **リリース** は各リポジトリの未出荷のリリースをライン順に一覧表示します：**次のリリース** または **計画中** 付きのバージョン、タイトル、手動で設定したバージョンには **手動で設定**、リリース内のすべてのタスクについての「{done}/{total}」の進捗バー、そしてそのタスクを持つ worklane、なければ **まだタスクなし**。行をクリックすると、それらの worklane のうち最初のもの（なければ `main`）のタイムラインがそのリリースの位置で開きます。リリースしない設定のリポジトリには **このリポジトリはリリースしません** と表示されます。

どちらのページでもリリースの計画、編集、移動はできません。worklane のタイムラインから行ってください。

### worklane 名の下の 1 行

プロジェクト、組織のページ、プロジェクトのリポジトリ、worklanes のすべての worklane の行には、名前の下に 1 行が表示されます：作業中は作業しているタスクのステータスと「{ID} {タイトル}」、空きのときは「次：{ID} {タイトル}」、残っているタスクがなければ **待機中のタスクなし**。

## サイドバーへのピン留め

ピン留めすると、プロジェクトが自分のサイドバーに表示されます。ピン留めは個人の設定で、ほかのメンバーには影響しません。

## 作成、編集、削除

プロジェクトの作成と編集はワークスペースのメンバーなら誰でもできます。削除できるのは `owner` と `admin` だけです。

<Callout type="warning">
プロジェクトを削除しても中のタスクは削除されません。タスクは紐づけが解除され、ワークスペースにそのまま残ります。プロジェクトの説明は完全に削除されます。
</Callout>
