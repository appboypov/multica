프로젝트는 제품 출시, 마이그레이션, 단계적으로 진행하는 기능처럼 여러 [태스크](/issues)를 함께 완료해야 하는 작업을 구성할 때 사용합니다.

하나의 태스크로 충분히 설명할 수 있는 작업에는 프로젝트가 필요하지 않습니다. 프로젝트는 공동 목표가 있고 진행 상황을 한곳에서 추적해야 하거나 저장소와 작업 디렉터리를 공유해야 하는 작업 묶음에 적합합니다.

## 프로젝트의 구성

| 내용 | 용도 |
|---|---|
| **이름, 아이콘, 설명** | 목표, 범위, 장기적으로 적용되는 요구 사항입니다. 설명은 프로젝트 안에서 실행되는 에이전트의 컨텍스트에 포함됩니다. |
| **조직** | 프로젝트가 속한 조직이거나 **조직 없음**입니다. |
| **우선순위** | `urgent`, `high`, `medium`, `low`, `none` 중 하나입니다. |
| **담당자(lead)** | 프로젝트 조율 책임자를 나타내는 멤버 또는 에이전트입니다. |
| **태스크와 진행률** | 프로젝트에 속한 작업과 완료 비율입니다. |
| **리소스** | 연결된 GitHub 저장소 또는 지정한 컴퓨터의 로컬 디렉터리입니다. |

## 조직

조직은 프로젝트를 묶습니다. 예를 들어 프로젝트가 일하는 회사나 고객별로 묶을 수 있습니다. 하나의 프로젝트는 최대 하나의 조직에 속합니다. **새 프로젝트**를 만들 때 조직을 선택해야 하며, 프로젝트 속성의 **조직** 행에서 바꿀 수 있습니다.

- **프로젝트** 페이지는 프로젝트를 조직별로 이름순으로 묶어 보여 주며, 조직이 없는 프로젝트는 마지막의 **조직 없음**에 표시됩니다. 그룹 행을 클릭하면 그룹이 접힙니다.
- 사이드바에서 프로젝트 다음에 있는 **조직** 페이지는 모든 조직과 각 조직의 프로젝트 수를 보여 줍니다. 행을 클릭하면 조직 페이지가 열리고 그 조직의 프로젝트가 표시됩니다. 거기서 **새 프로젝트**를 누르면 프로젝트가 그 조직에 속한 채로 만들어집니다.
- **새 조직**은 이름과 키(key)를 묻습니다. 조직 이름은 대소문자를 구분하지 않고 서로 달라야 합니다.
- **키**는 조직의 폴더 이름입니다. 영문 소문자, 숫자, 대시만 쓸 수 있고 영문자나 숫자로 시작해야 하며 워크스페이스 안에서 고유해야 합니다. 조직 페이지에서 바꿀 수 있습니다.

조직은 이름을 바꾸거나 삭제할 수 없습니다.

## 프로젝트와 태스크의 관계

하나의 프로젝트에는 여러 태스크가 포함될 수 있고, 하나의 태스크는 최대 하나의 프로젝트에만 속할 수 있습니다. 프로젝트에서 바로 태스크를 만들거나 태스크 속성에서 프로젝트를 선택하거나 변경할 수 있습니다.

프로젝트 진행률은 연결된 태스크를 기준으로 자동 계산됩니다.

```text
진행률 = 상태가 done 또는 cancelled인 태스크 수 ÷ 프로젝트의 전체 태스크 수
```

`cancelled`는 해당 작업이 프로젝트 범위에서 종료되었다는 뜻이므로 진행률에 포함됩니다.

## 프로젝트 설명과 실행 컨텍스트

에이전트가 프로젝트 안의 태스크를 실행할 때 프로젝트 이름과 설명이 해당 실행의 컨텍스트에 포함됩니다. 모든 관련 작업에 필요한 목표, 기술적 경계, 납품 규칙을 설명에 저장하세요. 하나의 태스크에만 관련된 요구 사항은 해당 태스크에 작성합니다.

## 리소스 추가

프로젝트 리소스는 에이전트가 사용할 코드와 작업 디렉터리를 지정합니다.

- **GitHub 저장소**: checkout할 수 있는 저장소와 선택적 ref를 제공합니다.
- **로컬 디렉터리**: 지정한 컴퓨터의 런타임이 기존 디렉터리에서 작업하게 하며, 에이전트가 디렉터리 내용을 직접 수정합니다.

선택 방법과 안전 경계는 [프로젝트 리소스](/project-resources)를 참고하세요.

## 프로젝트 담당자

Lead는 프로젝트 조율 책임자를 나타내는 멤버 또는 에이전트입니다. 권한 설정이 아니며 프로젝트의 태스크를 자동으로 할당하지 않습니다. 에이전트를 lead로 지정해도 자동 실행되지 않습니다. 실행을 시작하려면 여전히 태스크 할당, @멘션, 자동화 트리거 중 하나가 필요합니다.

## worklane에서 작업하기

worklane 페이지는 태스크를 세 가지 보기로 보여 줍니다. 페이지 상단에서 보기를 고르며, 페이지는 **타임라인**으로 열립니다.

- **타임라인**은 저장소 라인의 릴리스를 순서대로 보여 주고, 각 릴리스에 속한 이 worklane의 태스크를 함께 보여 줍니다.
- **보드**는 worklane의 태스크를 상태별 열로 보여 주며, **취소됨** 열은 숨겨져 있습니다. 카드를 다른 열로 끌면 상태가 바뀝니다. Multica는 "REBL-76을(를) In Review(으)로 옮겼습니다"라고 알려 주고, 변경에 실패하면 카드를 원래 자리로 되돌립니다. 열의 **+**는 그 열의 상태, 이 worklane, 저장소의 다음 릴리스가 채워진 **새 태스크**를 엽니다.
- **리스트**는 라인 순서대로 릴리스마다 구역을 보여 줍니다. 버전과 상태, 제목, 직접 정한 버전이면 **직접 설정**, 이 worklane의 태스크 진행(예: "3개 중 1개 완료") 또는 **이 worklane의 태스크 없음**, 릴리스 메뉴와 설명, 그리고 태스크가 이어집니다. 그 뒤에는 릴리스가 없는 이 worklane의 태스크를 담은 **릴리스 없음**이 있을 때만 나옵니다.

어느 보기에서든 태스크를 클릭하면 보기 옆에 미리보기가 열립니다. 미리보기 맨 위에는 유형, ID, 제목, 상태, worklane, 릴리스, 담당자가 있고 그 아래에 설명이 이어집니다. **태스크 열기**는 태스크 페이지를 엽니다.

상단의 **유형** 필터에서 여덟 가지 유형 중 하나 이상을 고르거나, 유형이 없는 태스크를 보려면 **유형 없음**을 고릅니다. 그러면 모든 보기가 고른 유형만 보여 주며, 보기를 바꿔도 선택이 유지됩니다.

### 작업 중과 대기

worklane의 태스크 중 In Progress 또는 In Review 상태인 태스크가 worktree의 브랜치를 차지하고 있으면 worklane은 **작업 중**이고, 그렇지 않으면 **대기**입니다. 상단에는 무엇을 하고 있는지 표시됩니다.

- 작업 중일 때는 브랜치를 차지한 태스크를 **now: {ID} {제목}**으로 보여 줍니다.
- 대기일 때는 완료되거나 취소되지 않은 첫 태스크를 **next: {ID} {제목}**으로 보여 줍니다. 릴리스를 라인 순서대로, 그다음 릴리스 없음을 보며, 각각 안에서는 가장 먼저 만든 태스크를 고릅니다.
- worklane의 모든 태스크가 완료되거나 취소되었으면 둘 다 보여 주지 않습니다.

### worklane의 worktree에서 일하는 에이전트

worklane 태스크에 대한 에이전트의 작업은 그 worklane의 worktree에서, 태스크의 브랜치 위에서 실행됩니다. `main`은 저장소의 체크아웃에서 실행됩니다. worklane은 한 번에 하나의 작업만 실행합니다. 에이전트의 런타임이 worklane과 다른 머신에 있으면 작업은 거부되고, 작업에 그 이유가 표시됩니다.

브랜치를 차지한 태스크의 풀 리퀘스트가 기본 브랜치에 병합되면, worktree는 가져온 기본 브랜치에서 만든 다음 태스크의 브랜치로 전환됩니다. 남은 태스크가 없으면 분리(detached) 상태가 됩니다. 잃을 것이 없을 때만 전환합니다. 커밋하지 않은 변경이나 푸시하지 않은 커밋이 있으면 현재 브랜치에 머물고, worklane의 활동에 그 이유가 남습니다.

## 사이드바에 고정

고정한 프로젝트는 내 사이드바에 표시됩니다. 고정은 개인 설정이며 다른 멤버에게 영향을 주지 않습니다.

## 생성, 수정, 삭제

모든 워크스페이스 멤버가 프로젝트를 만들고 수정할 수 있습니다. 삭제는 `owner`와 `admin`만 할 수 있습니다.

<Callout type="warning">
프로젝트를 삭제해도 그 안의 태스크는 삭제되지 않습니다. 태스크는 프로젝트와 연결이 해제된 뒤 워크스페이스에 계속 남습니다. 프로젝트의 설명과 리소스는 영구적으로 삭제됩니다.
</Callout>
