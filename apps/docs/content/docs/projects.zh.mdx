项目用来组织需要多条 [任务](/issues) 一起完成的工作，例如一次产品发布、一次迁移，或一个分阶段推进的功能。

一条任务能说清的工作不需要项目。项目适合有共同目标、需要统一跟进进度，或在同一批仓库中进行的一组工作。

## 项目的组成

| 内容 | 用途 |
|---|---|
| **名称、图标和描述** | 目标、范围和长期有效的要求；描述会进入项目内智能体的执行上下文。 |
| **组织** | 项目所属的组织，或 **无组织**。 |
| **优先级** | `urgent`、`high`、`medium`、`low` 或 `none`。 |
| **负责人（lead）** | 成员或智能体，表示谁负责协调项目。 |
| **任务和进度** | 项目中的工作及其完成比例。 |
| **仓库** | 项目所用的 GitHub 仓库，每个仓库带有自己的检出目录和工作线。 |

![项目详情：按状态分列的任务、进度与项目描述](/images/docs/project-detail.webp)

## 组织

组织用来归类项目，例如按项目服务的公司或客户。一个项目最多属于一个组织。**新建项目**时必须选择组织，之后可以在项目属性的 **组织** 一行中更改。

- **项目** 页面按组织分组显示项目，组按名称排序，没有组织的项目归入最后的 **无组织**。点击组所在的行即可折叠该组。
- 侧边栏中“项目”之后的 **组织** 页面列出每个组织及其项目数。点击一行会打开该组织的页面，其中列出它的项目；在那里点击 **新建项目**，项目会直接属于该组织。
- **新建组织** 需要填写名称和键（key）。组织名称不能重复（不区分大小写）。
- **键** 是组织的文件夹名：只能包含小写字母、数字和短横线，以字母或数字开头，并且在工作区内唯一。可以在组织页面中更改。

组织不能重命名或删除。

## 项目和任务的关系

一个项目可以包含多条任务，一条任务最多属于一个项目。可以在项目中直接创建任务，也可以在任务属性中选择或更换项目。

项目进度按关联任务自动计算：

```text
进度 = 状态为 done 或 cancelled 的 issue 数 ÷ 项目中的全部 issue 数
```

`cancelled` 表示这项工作已从项目范围中结束，因此计入进度。

## 项目描述与执行上下文

智能体执行项目内的任务时，项目名称和描述会加入本次执行的上下文。描述适合保存所有相关运行都需要的信息：目标、技术边界、交付约定。只与单条任务相关的要求写在该任务中。

## 仓库

项目包含它所用的 GitHub 仓库。项目页面的标题处显示仓库数量，并按 `owner/name` 为每个仓库显示一张卡片：默认分支和工作线，第一条是在仓库检出目录中的 `main`。点击卡片标题可将其折叠。在**项目**和组织页面上，项目行可以展开为每个仓库一行。

- **仓库**会打开**添加仓库**。它列出工作区的 [GitHub App](/github-integration) 能看到的所有仓库，并显示私有或公开以及默认分支。一个仓库最多属于一个项目：已在某个项目中的仓库会显示该项目的名称，不能选择。**缺少某个仓库？在 GitHub 上授予 Multica 访问权限**会打开 App 的安装页面。
- **检出目录**选择一台机器以及仓库常规检出所在的文件夹，默认是 `~/Repos/{name}`。Multica 会在那台机器上检查该文件夹：它必须是该仓库的 git 检出，并位于默认分支上。如果那里没有文件夹，**克隆到这里**会把仓库克隆过去。
- **发布**选择仓库版本的来源：检出目录中找到的版本文件（`pubspec.yaml`、`Cargo.toml`、`pyproject.toml` 或 `package.json`）、**仅标签**，或**此仓库不发布**。
- 卡片菜单中有**编辑仓库**和**移除仓库**。编辑仓库可以修改检出目录和发布方式，但不能更换仓库；移除仓库会把仓库及其工作线 `main` 从 Multica 中移除，检出文件夹会原样保留在机器上。仓库除了 `main` 还有其他工作线时，需先移除它们才能移除仓库。

## 项目负责人

Lead 可以是成员或智能体，表示谁负责协调项目。它不是权限设置，不会自动分配项目中的任务；把智能体设为 lead 也不会自动运行它。启动执行仍需分配任务、@提及或自动化触发。

## 在 worklane 中工作

worklane 的页面用三种视图显示它的任务。在页面顶部选择视图；页面默认打开 **时间线**。

- **时间线** 按版本线的顺序显示仓库的版本，以及每个版本中属于此 worklane 的任务。
- **看板** 按状态分列显示 worklane 的任务，**已取消** 一列默认隐藏。把卡片拖到另一列即可更改状态：Multica 会提示“REBL-76 已移至In Review”，更改失败时卡片会回到原处。列上的 **+** 会打开 **新建任务**，并带上该列的状态、此 worklane 及其仓库的下一个版本。
- **列表** 按版本线的顺序为每个版本显示一个分组：版本号和状态、标题、手动设定的版本号显示 **手动设定**、此 worklane 在其中的任务完成情况（例如“3 个中已完成 1 个”）或 **没有此 worklane 的任务**、版本菜单和版本描述，然后是任务。之后是 **无版本**，列出此 worklane 中不属于任何版本的任务（有时才显示）。

在任一视图中点击任务，会在视图旁打开任务预览。预览顶部依次是类型、ID、标题、状态、worklane、版本和负责人，然后是描述。**打开任务** 会打开任务自己的页面。

页面顶部的 **类型** 筛选可以选择八种类型中的一种或多种，或选择 **无类型** 来显示没有类型的任务。之后每个视图只显示所选类型，切换视图时筛选保持不变。

### 忙碌和空闲

当 worklane 的某个处于 In Progress 或 In Review 的任务占用着它的工作树分支时，worklane 为 **忙碌**，否则为 **空闲**。页面顶部会显示它在做什么：

- 忙碌时显示 **正在做：{ID} {标题}**，即占用分支的任务。
- 空闲时显示 **下一个：{ID} {标题}**，即第一条未完成且未取消的任务：先按版本线顺序看各版本，再看无版本，同一组内取最早创建的任务。
- 当 worklane 的所有任务都已完成或已取消时，两者都不显示。

### 智能体在 worklane 的工作树中工作

智能体执行 worklane 中任务时，会在该 worklane 的工作树中、在任务的分支上运行；`main` 则在仓库的检出目录中运行。一个 worklane 同一时间只运行一个任务。如果智能体的运行时与 worklane 不在同一台机器上，任务会被拒绝，并说明原因。

当占用分支的任务的拉取请求合并到默认分支后，工作树会切换到下一条任务的分支（从拉取后的默认分支创建）；没有剩余任务时，工作树会处于分离状态。只有在不会丢失任何内容时才会切换：工作树中有未提交的更改或未推送的提交时，它会留在当前分支，worklane 的动态会说明原因。

## 版本

仓库的版本组成一条版本线，按发布顺序排列。仓库的每个 worklane 都在 **时间线** 上显示同一条版本线：第一个未发布的版本是 **下一个版本**，其后的版本为 **已规划**。worklane 页面顶部显示 **最近发布 v{版本号}**、**尚未发布任何版本** 或 **不发布版本**。在项目页和组织页上，每一行 worklane 会在 **上一个 · 下一个 · 已规划版本** 下显示其仓库上一个已发布和下一个版本；点击版本即可在该 worklane 的时间线上打开它。

- 时间线末尾的 **规划版本** 会在最后一个版本之后添加一个版本。选择 **补丁**、**次要** 或 **主要**，在前一个版本（第一个版本则为最新标签）的版本号上递增，或选择 **自定义** 手动设定版本号。每个版本号都必须高于前一个：不满足时，对话框会说明原因，**规划版本** 保持禁用。
- 手动设定的版本号显示 **手动设定**，版本线变化时保持不变。递增得到的版本号跟随前一个版本。
- 未发布版本的菜单提供 **编辑版本**、**提前**、**推后** 和 **移除版本**。**编辑版本** 可修改版本号、标题和描述。移动或移除版本会重新计算其后递增得到的版本号；如果移动会让某个版本号不高于前一个，该操作会被禁用并说明原因。
- 每次更改都会出现在仓库每个 worklane 的动态中，每个变化的版本号单独一行，例如“Notifications v1.2.0 -> v1.1.0”。

版本在发布之前没有日期，也没有目标。

### 不发布版本的仓库

在 **编辑仓库** 中把 **版本** 设为 **此仓库不发布版本** 后，它的 worklane 会显示“{owner/name} 不发布版本，因此它的 worklane 不规划版本。”，取代规划版本。版本线上还有未发布的版本时，仓库不能停止发布：编辑仓库会列出这些版本，并请你先移除它们。重新选择 **仅标签** 或某个版本文件后，规划版本会从最新标签开始。

## worklanes 和版本

**worklanes** 和 **版本** 位于侧边栏的“工作”下，排在“组织”之后。两个页面都按组织、项目和仓库列出工作区的工作，顺序与“项目”页面一致，没有可列内容的分组不会显示。所有分组默认展开；点击箭头或分组所在行即可折叠。点击组织或项目的名称会打开它的页面。

- **worklanes** 列出每一个 worklane，每个仓库下 `main` 排在最前。每个仓库显示它的默认分支和 **+ Worklane**，点击后为该仓库打开“新建 worklane”。worklane 的每一行显示它在做什么以及它的版本：上一个已发布的版本、下一个版本及其中本 worklane 任务的 “{done}/{total}”，以及之后最多两个已规划的版本。点击该行会打开 worklane 的时间线。
- **版本** 按版本线顺序列出每个仓库尚未发布的版本：版本号及 **下一个版本** 或 **已规划**、标题、手动设置的版本号会标注 **手动设置**、按版本中全部任务计算 “{done}/{total}” 的进度条，以及包含其任务的 worklane；没有任务时显示 **还没有任务**。点击该行会打开这些 worklane 中第一个的时间线（没有则为 `main`），并定位到该版本。设置为不发布的仓库显示 **此仓库不发布版本**。

这两个页面都不能规划、编辑或移动版本：请在 worklane 的时间线中操作。

### worklane 名称下的一行

在“项目”、组织页面、项目的仓库和 worklanes 页面中，每个 worklane 行的名称下都有一行：忙碌时显示正在处理的任务的状态和 “{ID} {标题}”，空闲时显示 “下一个：{ID} {标题}”，没有剩余任务时显示 **没有排队的任务**。

## 固定到侧边栏

固定后，项目出现在你的侧边栏中。固定是个人偏好，不影响其他成员。

## 创建、编辑和删除

工作区成员都可以创建和编辑项目；只有 `owner` 和 `admin` 可以删除。

<Callout type="warning">
删除项目不会删除其中的任务：它们解除关联后继续保留在工作区；项目的描述会被永久删除。
</Callout>
