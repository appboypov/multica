创建智能体前，需要先有一个可用的[运行时](/daemon-runtimes)。运行时决定这名智能体使用哪台电脑和哪款 AI 编程工具；智能体则保存它长期使用的身份、指令和能力。

在工作区的 **智能体** 页面点 **新建智能体**。

## 选择起点

创建页面提供两种方式：

| 方式 | 适合什么情况 |
|---|---|
| **从空白开始** | 已经知道智能体的职责，想自己填写每项配置。 |
| **通过 AI 创建** | 先描述目标，让 Agent Builder 追问关键信息并生成草稿。 |

通过 AI 创建需要一个在线运行时来完成 Builder 对话。无论选择哪种方式，创建前都可以检查并修改最终配置。

![创建智能体的起点选择页：Start blank 与 Build with AI](/images/docs/quickstart-new-agent.webp)

## 必填项

创建智能体只要求两项：

- **名称**：在当前工作区中必须唯一。
- **运行时**：选择实际运行的环境。

其他字段可以先使用默认值，创建后再调整。新智能体默认只有创建者可以运行。

## 描述与指令

**描述**是写给团队看的简短介绍，只显示在智能体列表和详情中，不会进入 AI 编程工具的提示。描述没有长度限制：超过 255 个字符时，计数器会提示已超出建议长度，描述仍可保存。

**指令**会在每次执行时提供给智能体，通常包含：

- 它负责什么、不负责什么；
- 收到工作后先检查什么；
- 允许修改哪些内容；
- 结果的提交方式；
- 什么时候需要向成员确认。

例如：

```text
你负责审查前端 Pull Request。

先阅读改动和相关测试，只检查：
- React 与 TypeScript 的正确性
- 可访问性
- 与现有组件模式是否一致

不要直接修改代码。把问题按严重程度写在 issue 评论中；
没有阻塞问题时，明确说明可以合并。
```

### 选择文件和文件夹

指令还可以在每次执行时载入运行时所在电脑上的文件和文件夹，让智能体把你保存在本地的 skill 或笔记当作实时指令。所选内容显示在指令下方，创建页、创建对话框和智能体的**指令**标签页中都有。

智能体运行时的所有者点击**浏览**，即可列出这台电脑上该运行时 AI 编程工具的 skill 根目录（例如 `~/.omp/agent/skills`），再打开文件夹或输入绝对路径。可以跨多个文件夹勾选文件和文件夹，然后点击**添加**：它们会按添加顺序以标签形式显示在指令下方。隐藏条目（名称以 `.` 开头）也会列出，标记为隐藏，并且可以选择。运行时离线时，浏览窗口不列出任何内容，也不会添加；已选的标签仍可移除。

所选内容会载入到指令中 `{selection}` 所在的位置。第一次添加路径时，`{selection}` 会插入到光标处；如果指令从未获得焦点，则插入到末尾。你可以移动它，也可以写多次。每次执行开始时，运行时所在电脑上的守护进程会从磁盘读取所选路径，把每个 `{selection}` 替换为每个所选文件夹的文件树和每个文本文件的内容，按选择顺序排列。所选文件夹会跳过隐藏文件和文件夹、二进制文件，以及 git 仓库中被 git 忽略的文件；你亲自选择的路径总会被读取。磁盘上的修改会在下一次执行时生效，无需重新保存智能体。

两者不一致时，字段会给出提示：选择了路径但指令中没有 `{selection}`，所选内容不会载入；或者指令中有 `{selection}` 但没有选择任何路径，它会保持为空。两种提示都不会阻止保存。如果所选路径不存在或无法读取，或所选文件不是文本文件，执行会在智能体启动前失败，显示**指令选择出错**，错误中会写明该路径，并且不会重试。

只有智能体运行时的所有者可以浏览这台电脑，并添加或移除所选路径。其他能看到该智能体的人只会看到只读的路径标签；有编辑权限的成员仍可修改指令文本，所选内容保持不变。

## 添加 skill

创建时可以从工作区选择一个或多个 [skill](/skills)。

Skill 适合保存可以跨智能体复用的方法和资料；只属于这名智能体的长期要求写在指令中。

## 对话开场建议

最多添加三条**对话开场建议**，让用户在发送第一条消息前了解这个智能体擅长什么。它们出现在别人与该智能体开始新对话时，位于输入框上方。每项包含一个简短标题和一条完整提示词，两者都必须填写。选择后只会填入输入框，用户可以先检查或修改，不会自动开始执行。

标题和提示词没有长度限制。标题超过 80 个字符、提示词超过 4,000 个字符时，编辑器会给出提示，开场建议仍可保存。

编辑器下方会预览新对话的实际效果；有编辑权限的人还会在那个空状态里看到**自定义开场建议**入口，点击可直接跳回这里。

留空时，对话页会显示本地化的通用默认值。针对智能体职责和边界编写的示例通常更有帮助。

CLI 可用 `agent create` / `agent update` 的 `--conversation-starters` 设置（`{"label","prompt"}` 对象的 JSON 数组；更新时传 `'[]'` 清空）。`agent copy` 仍只搬运源值，没有覆盖 flag。

## 选择运行时、模型和思考强度

运行时已经对应一款 AI 编程工具。选择运行时后，可以继续选择该工具支持的模型和思考强度；部分工具（如 Codex）还可选择速度档：

- 留空时，使用运行时或本地 CLI 的默认配置。
- 设置模型后，该智能体之后领取运行时会使用这个覆盖值。
- 某些运行时自行管理模型，因此不会显示模型选择。

不同工具支持的模型、会话恢复、skill 和 MCP 能力不同，见[AI 编程工具对照](/providers)。

## 设置 Access

Access 决定哪些成员可以运行这名智能体（分配、@提及或对话）：

| Access | 含义 |
|---|---|
| **仅自己**（Only me） | 只有你可以运行。默认选项。 |
| **整个工作区**（Entire workspace） | 所有工作区成员都可以运行。 |
| **指定成员**（Specific people） | 只有你和选中的成员可以运行。 |

![Access 设置：仅自己、整个工作区、指定成员三档](/images/docs/agent-access-settings.webp)

只有智能体 owner 可以修改 Access，工作区管理员也不行。工作区 `owner` 和 `admin` 可以管理其他配置，但不能借管理员身份运行未授权的智能体。

## 创建后的配置项

打开智能体详情页，可以继续调整：

| 配置 | 作用 |
|---|---|
| **并发上限** | 同一名智能体最多同时执行多少次运行，默认是 6；达到上限后继续排队。 |
| **环境变量** | 在 AI 编程工具启动时注入变量。 |
| **自定义参数** | 逐项追加到 AI 编程工具的 CLI 参数中。 |
| **MCP** | 为支持的 AI 编程工具提供 MCP server 配置。 |
| **集成** | 连接这名智能体可以使用的外部服务。 |

运行时所在的守护进程还有一个全局并发上限（默认 20），实际并发取两者中的较小值。

修改配置不会改变已经开始的运行。后续运行被运行时领取时，会使用当时保存的智能体配置。

## 环境变量与凭据

环境变量适合放这名智能体执行时需要的有限权限凭据，例如只读 API key 或单一 scope 的 token。

<Callout type="warning">
**`custom_env` 的值在 Multica 服务器的数据库里是明文存储的**，不属于"只留在本机"的数据。agent list/get 接口不再返回任何 env 值，只返回键的数量；只有工作区 `owner`、`admin` 可以解锁和修改，并且每次读取或修改都会留下审计记录。运行中的智能体不能调用管理接口读取其他智能体的变量。
</Callout>

不要使用生产数据库的管理员密码或其他高价值长期凭据。

`PATH`、`HOME` 和 `MULTICA_*` 等运行环境关键变量不能通过这里覆盖。

## 自定义参数和 MCP

自定义参数按数组逐项传给 AI 编程工具，不经过 shell 展开。参数名称是否有效由对应工具决定；已有独立字段的模型配置不需要在这里重复设置。

<Callout type="warning">
不要把凭据或其他 secret 放进自定义参数。它们会留在子进程的 argv 中，同机其他进程可能通过 `ps` 或 `/proc` 看到；请改用环境变量（`custom_env`）。守护进程日志会遮蔽参数值，但无法保护操作系统的进程列表。
</Callout>

MCP 配置可能包含 token，保存与展示规则和环境变量相同。只有支持托管 MCP 配置的运行时会显示这一项；不支持的工具不会因为保存了配置就自动获得 MCP 能力。

## 复制智能体

复制会带上名称之外的大部分工作配置，包括指令、所选文件和文件夹、对话开场建议、skill、自定义参数、头像、并发上限和 Access 设置。模型、思考强度和速度档也会一并带走；如果原运行时不可用、复制被迫换到其他运行时，这三项会清空，需要重新选择。

环境变量的值和 MCP 配置在任何情况下都不会复制，需要在新智能体中重新设置。复制会保留原智能体的运行时绑定和 Access 设置。只有副本所在运行时的所有者，才能创建带有所选文件和文件夹的副本。

## 使用 CLI 创建

```bash
multica agent create \
 --name "Frontend Reviewer" \
 --runtime-id <runtime-id> \
 --description "审查前端 Pull Request" \
 --instructions "先阅读改动和测试，只在 issue 评论中提交审查结论。" \
 --conversation-starters '[{"label":"审查 PR","prompt":"审查当前最相关的未合并 Pull Request。"}]'
```

命令行参数中的明文会进入 shell 历史；stdin 和权限受限的文件不会。

已有配置相近的智能体时，可以直接复制：

```bash
multica agent copy <agent-id>
```

默认复制到同一运行时；加 `--runtime-id` 换到其他运行时，必须同时指定 `--model`。环境变量、MCP 配置和 `runtime_config` 永不复制；运行时绑定本身会保留。完整参数见[使用 CLI](/cli)。
